# Android Screen · macOS

**Версия 2.3.2** — графическая оболочка на SwiftUI для [scrcpy](https://github.com/Genymobile/scrcpy): отображение экрана Android на Mac и управление мышью и клавиатурой через ADB по Wi-Fi.

- macOS 12+, Apple Silicon или Intel;
- поиск уже доступных Wi-Fi-устройств через ADB;
- настройка сетевого ADB через USB прямо в приложении;
- настройка IP/порта и выбор scrcpy через GUI;
- встроенные scrcpy и ADB загружаются установщиком из официальных источников;
- локальная сборка приложения из исходников Swift, без Homebrew.

> Это неофициальная оболочка. Она не входит в проекты Google или Genymobile. Установщик загружает сторонние бинарники при необходимости; в Git-репозитории их нет.

## Установка из GitHub

1. Скачайте исходники репозитория через **Code → Download ZIP** или клонируйте репозиторий. Либо скачайте приложенный к [GitHub Releases](../../releases) архив для macOS, если он опубликован.
2. Полностью распакуйте архив. В macOS откройте **`Установить Android Screen.command`** двойным кликом.
3. Установщик использует Apple Command Line Tools для сборки SwiftUI, затем проверяет или загружает scrcpy и ADB во внутренний каталог приложения. Если CLT отсутствуют, macOS предложит их установить; затем повторите запуск.
4. Приложение появится по адресу `~/Applications/Android Screen.app`. Откройте его и следуйте инструкции подключения по Wi-Fi.

При загрузке ADB установщик попросит подтвердить условия лицензии Android SDK от Google. Для первой установки нужен доступ к GitHub и Google. Системные копии scrcpy и ADB не изменяются.

Порядок публикации проекта через GitHub Desktop описан в [docs/GITHUB_DESKTOP.md](docs/GITHUB_DESKTOP.md). История изменений — в [CHANGELOG.md](CHANGELOG.md).

## Подробная документация

## Коротко: что нужно сделать

1. Используйте Mac с **macOS 12+** (Apple Silicon или Intel) и работающим интернетом для первой установки.
2. Распакуйте скачанный ZIP-архив целиком (или используйте клонированный репозиторий).
3. Запустите **`Установить Android Screen.command`** двойным кликом.
4. Установщик проверит Apple Command Line Tools, соберёт приложение, проверит **встроенные** scrcpy и adb и **скачает отсутствующие** с GitHub и Google. При первой загрузке ADB потребуется принять условия Android SDK от Google.
5. После завершения откройте `~/Applications/Android Screen.app`, укажите IP-адрес и порт Android, проверьте соединение и начните трансляцию.

**Homebrew, Android Studio и ручная установка scrcpy/ADB не требуются.** На Android-устройство само приложение scrcpy устанавливать не нужно.

## Что именно устанавливается

| Компонент | Назначение | Установка / официальный источник |
| --- | --- | --- |
| **Android Screen 2.3.2** | Графический интерфейс | Установщик создаёт `~/Applications/Android Screen.app` |
| **scrcpy 5.0.1** | Видео и управление Android | Устанавливается внутрь `.app` из [официального релиза scrcpy](https://github.com/Genymobile/scrcpy/releases/tag/v5.0.1) |
| **ADB / Android SDK Platform-Tools** | Подключение по USB и Wi-Fi | Устанавливается внутрь `.app` из [официального архива Google](https://developer.android.com/tools/releases/platform-tools) |
| **Apple Command Line Tools** | Swift-компилятор и macOS SDK для сборки приложения | **Системный** компонент Apple, устанавливается отдельно через `xcode-select --install` |

Расположение встроенных инструментов:

```text
~/Applications/Android Screen.app/
  Contents/
    MacOS/AndroidScreen
    Resources/Tools/
      scrcpy/scrcpy
      scrcpy/scrcpy-server
      platform-tools/adb
```

Полные каталоги официальных архивов сохраняются в `.app` (включая дополнительные библиотеки и файлы). Обновление или удаление Android Screen **не изменяет** Homebrew, системные пути, Android Studio или независимо установленный scrcpy.

### Как работает автоматическая проверка

- Если предыдущая версия Android Screen **уже содержит рабочие встроенные утилиты**, установщик переносит их в новую сборку без повторной загрузки.
- Если компонента внутри приложения нет, установщик скачивает официальную macOS-сборку для соответствующей архитектуры Mac.
- Для `scrcpy 5.0.1` установщик сверяет **SHA-256** с суммой, опубликованной разработчиками. Для ADB проверяет загрузку по HTTPS и целостность ZIP; Google публикует по используемой ссылке обновляемый архив, поэтому фиксированной контрольной суммы в установщике нет.
- До замены предыдущего приложения установщик проверяет, что скачанные утилиты запускаются (`scrcpy --version`, `adb version`), и выполняет локальную подпись сборки.
- Если на любом этапе возникнет ошибка, **старое приложение не заменяется**. При успешном обновлении оно перемещается в отдельную резервную копию в `~/Applications/`.

**Интернет:** при первой установке, когда встроенных инструментов ещё нет, нужен доступ к `github.com` и `dl.google.com`. При последующих переустановках из уже укомплектованного `.app` скачивание обычно не требуется. Если GitHub/Google недоступны, установщик покажет адрес, загрузка с которого не удалась.

**Условия Google:** перед загрузкой Android SDK Platform-Tools установщик показывает [официальную страницу](https://developer.android.com/tools/releases/platform-tools) и запрашивает подтверждение принятия условий лицензии. Без подтверждения ADB не скачивается и установка прекращается, не затрагивая старую версию приложения.

### Если нет Apple Command Line Tools

Это исключение: Swift и macOS SDK нельзя просто скопировать в папку приложения. Установщик проверяет их наличие и при необходимости вызывает системный запрос Apple:

```bash
xcode-select --install
```

Подтвердите установку в окне macOS, дождитесь её окончания и **запустите установщик Android Screen повторно**. Если инструменты уже есть, дополнительно устанавливать их не нужно. Полный Xcode не обязателен.

## Как подключить Android по Wi-Fi

Mac и Android должны находиться в одной сети (без клиентской изоляции). Рекомендуется использовать доверенную локальную сеть. На Android требуется разрешить отладку и сопряжение с этим Mac.

Все приведённые ниже команды запускают **встроенный ADB**. Сначала откройте Терминал и задайте удобную переменную:

```bash
ADB="$HOME/Applications/Android Screen.app/Contents/Resources/Tools/platform-tools/adb"
"$ADB" version
```

### Вариант 1: на Android есть «Беспроводная отладка»

На некоторых устройствах с Android 11+ есть раздел **Для разработчиков → Беспроводная отладка**.

1. Включите беспроводную отладку и выберите сопряжение по коду.
2. Выполните команду с **IP и портом сопряжения**, показанными на телефоне или планшете:

   ```bash
   "$ADB" pair 192.168.1.50:37123
   ```

3. Введите код, отображаемый Android.
4. На основном экране беспроводной отладки найдите **порт подключения** (он может отличаться от порта сопряжения) и подключитесь:

   ```bash
   "$ADB" connect 192.168.1.50:39817
   "$ADB" devices -l
   ```

5. В Android Screen укажите **IP и порт подключения** (в примере `192.168.1.50` и `39817`), нажмите **«Проверить соединение»**.

IP-адреса и порты здесь приведены только как примеры. См. [документацию Android о подключении по Wi-Fi](https://developer.android.com/tools/adb#wireless-android11-command-line).

### Вариант 2: «Беспроводной отладки» нет — первый запуск по USB

1. Подключите Android к Mac кабелем, поддерживающим передачу данных. Включите **«Отладка по USB»** в настройках разработчика и подтвердите доверие к Mac на Android.
2. Проверьте подключение:

   ```bash
   "$ADB" devices -l
   ```

   USB-устройство должно отображаться со статусом `device`.
3. Пока USB подключён, включите сетевой режим ADB:

   ```bash
   "$ADB" -d tcpip 5555
   ```

4. Узнайте настоящий IP Android в настройках Wi-Fi и выполните:

   ```bash
   "$ADB" connect 192.168.1.50:5555
   "$ADB" -s 192.168.1.50:5555 shell echo WIFI_OK
   ```

5. Убедитесь, что команда вернула `WIFI_OK`. Отключите USB и повторите проверку. Если соединение сохранилось, укажите IP и порт `5555` в Android Screen.

Если после отключения USB появляется `offline` или `Connection refused`, Android, возможно, выключает ADB TCP/IP. Это ограничение прошивки/сети, а не отсутствие утилит в Android Screen. Для некоторых устройств помогает смена режима USB, но универсального исправления нет.

## Автоматическое обнаружение: ограничения

Автопоиск **не сканирует локальную сеть** и не обходит ограничения Android. Он использует `adb devices -l` и проверяет доступность уже подключённых TCP/IP-устройств. Если IP изменился и ADB ещё не знает новый адрес, подключите устройство по USB и используйте в приложении кнопку **«Настроить подключение по Wi-Fi через USB»**. После подключения оно появится в автопоиске. Если устройство отключает ADB TCP/IP при извлечении USB, это не устраняется автоматическим обнаружением. При нескольких доступных устройствах автопоиск никого не выбирает, а ручная кнопка показывает список.

В интерфейсе есть единый блок **«Поиск и настройка подключения по Wi-Fi»**: ручной поиск уже подключённых ADB-устройств и настройка нового подключения через USB с пояснением различий. Пошаговая инструкция первого подключения раскрывается по нажатию. Для Android с отдельным переключателем «Беспроводная отладка» (Android 11+) сохраняется альтернативное сопряжение по коду через `adb pair` с указанием порта подключения.

## Графический интерфейс

- **IP / порт:** можно менять в главном окне и сохранять.
- **Исполняемый файл scrcpy:** при первой установке используется **встроенный**. В поле пути можно выбрать внешний scrcpy; кнопка **«Встроенный»** возвращает штатную версию.
- **Проверить соединение:** проверяет ADB по введённому адресу и при необходимости выполняет `adb connect`.
- **Автопоиск при запуске:** проверяет уже зарегистрированные и доступные TCP/IP-подключения ADB и автоматически подставляет IP/порт, если обнаружено ровно одно устройство. Не запускает трансляцию без нажатия кнопки. Если устройств несколько, настройки не меняются.
- **Найти устройство через ADB** (в общем блоке поиска и настройки): повторно проверяет доступные устройства по кнопке. Если их несколько, предлагает выбрать нужное из списка.
- **Настроить подключение по Wi-Fi через USB:** при подключённом кабеле и разрешённой USB-отладке определяет IP через Android, включает ADB TCP/IP на выбранном порту и проверяет связь. Используется по желанию для первичного подключения или после сброса ADB.
- **Автоматически искать Wi-Fi-устройство при запуске:** переключатель автоматической проверки ADB (сохраняется в настройках).
- **Начать / остановить трансляцию:** запускает или останавливает scrcpy.
- **Открыть журналы:** показывает каталог журналов для диагностики.

При обновлении с 2.1 настройки IP и порта сохраняются. Приложение переходит на встроенный scrcpy по умолчанию; внешний scrcpy можно снова выбрать через интерфейс. Настройки, сохранённые в 2.2 и новее с выбранной внешней версией, сохраняют этот выбор.

Файлы данных пользователя:

```text
~/Library/Application Support/Android Screen/settings.json
~/Library/Logs/Android Screen/last-session.log
```

## Если что-то не работает

| Симптом | Что делать |
| --- | --- |
| Установщик не находит Swift/macOS SDK | Завершите установку Apple Command Line Tools, проверьте `xcrun --sdk macosx --show-sdk-path`, повторите запуск |
| Не скачивается scrcpy | Проверьте доступ к [GitHub Releases](https://github.com/Genymobile/scrcpy/releases/tag/v5.0.1), интернет/VPN; при неудаче приложение останется прежним |
| Не скачивается ADB | Откройте [Android Platform-Tools](https://developer.android.com/tools/releases/platform-tools), проверьте доступ к `dl.google.com` и принятие условий |
| `Connection refused` | Проверьте IP, порт, наличие действующего режима беспроводной отладки и доступность устройства по сети |
| `offline` | Переподключите ADB, проверьте, не отключает ли Android сетевую отладку при извлечении USB |
| `unauthorized` | Разблокируйте Android и подтвердите запрос разрешения отладки |
| `more than one device/emulator` | Для ручных команд используйте `-s IP:PORT` или `-d` для USB |
| scrcpy мгновенно завершается | Откройте журналы Android Screen и проверьте сообщение об ошибке |
| Не найден встроенный инструмент | Запустите установщик снова; он восстановит отсутствующие файлы |

ADB даёт расширенный доступ к Android. Не пробрасывайте его порт в интернет и выключайте беспроводную отладку, когда она не требуется.
