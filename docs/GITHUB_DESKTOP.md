# Публикация через GitHub Desktop

Этот архив — **содержимое репозитория**, а не скомпилированное приложение. GitHub Desktop создаст локальный Git-репозиторий и опубликует его на вашем аккаунте.

## Первый коммит

1. Установите [GitHub Desktop](https://desktop.github.com/) и войдите в GitHub.
2. **File → New repository…**. Укажите имя `android-screen` (или другое) и папку на Mac. Не добавляйте лицензию автоматически, пока не решили, на каких условиях хотите распространять исходный код.
3. Нажмите **Create Repository**. GitHub Desktop создаст локальную папку репозитория.
4. Распакуйте ZIP исходников, откройте папку `android-screen` **внутри ZIP** и перенесите **её содержимое**, включая `.gitignore` и `.gitattributes`, в папку только что созданного репозитория. Не переносите `.git` из чужой папки, если она есть. Не заменяйте существующий `.git`.
5. В GitHub Desktop появятся новые файлы. Проверьте Changes, введите сообщение `Initial import: Android Screen 2.3.2` и нажмите **Commit to main**.
6. Нажмите **Publish repository**. Выберите видимость `Private` или `Public` осознанно; публичная публикация делает исходный код доступным всем.

Если GitHub Desktop уже создал `README.md` или `.gitignore`, замените их файлами из архива перед первым коммитом, чтобы не получить дубликатов.

## Публикация установочного архива

ZIP установки (`Android_Screen_2.3.2_macOS_ready.zip`) **не помещайте в сам Git-репозиторий**: он предназначен для GitHub Releases.

1. Откройте опубликованный репозиторий на github.com.
2. Выберите **Releases → Draft a new release**.
3. Создайте тег `v2.3.2` от коммита `main`.
4. Название релиза: `Android Screen 2.3.2`.
5. Добавьте краткое описание из `CHANGELOG.md` и загрузите установочный ZIP в раздел **Assets**.
6. Опубликуйте релиз.

GitHub Releases можно добавить после первого коммита и публикации репозитория. Приложение собирается локально на Mac при запуске `.command`; ZIP содержит исходники и установщик, а не готовый подписанный/нотариально заверенный `.app`.

## Лицензия

Лицензия **самого Android Screen** пока не выбрана и в архив не добавлена. Публичность репозитория сама по себе не делает проект open source в юридическом смысле. Перед распространением на условиях открытой лицензии выберите подходящий вариант (например, MIT или Apache-2.0), укажите правообладателя и добавьте `LICENSE` отдельным коммитом. У сторонних scrcpy и Android Platform-Tools собственные условия.
